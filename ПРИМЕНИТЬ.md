# Что внутри архива

Файлы кладутся в корень репозитория `actual_invest_tracker`, поверх существующих.

## 1. `.github/workflows/main.yml` — заменяет текущий

Что изменилось относительно твоей версии:

- добавлен блок `permissions: contents: write` — без него `gh release create`
  упадёт с ошибкой доступа;
- в сборку добавлен `--build-number=${{ github.run_number }}`, чтобы versionCode
  рос от сборки к сборке (сейчас он всегда 1, потому что `local.properties`
  в CI не существует);
- шаг `actions/upload-artifact@v4` заменён на публикацию APK в Releases.
  Ассеты релизов не расходуют квоту Actions storage — именно она и кончилась.

Остальные шаги (checkout, flutter-action, pub get, build_runner, analyze, test)
не тронуты.

## 2. `.gitignore` — новый файл

В репозитории его сейчас нет. Без него рано или поздно закоммитятся `build/`,
`.dart_tool/`, `local.properties` и сгенерированные `*.g.dart`.

Важно: `pubspec.lock` тоже в списке. Для приложения (а не библиотеки) его
обычно как раз коммитят, чтобы CI собирал те же версии пакетов, что и локально.
Если хочешь так — удали эту строку из `.gitignore`.

Если в репозиторий уже попало что-то из списка, после добавления файла нужен
один раз:

    git rm -r --cached .
    git add .
    git commit -m "Добавлен .gitignore"

## Проверка

После пуша открой вкладку Actions. Сборка должна дойти до шага
«Publish APK to Releases», а APK появится во вкладке Releases тегом
`build-<номер>`, а не в Artifacts.
